# 原版与天境：机制清单与实施顺序

更新日期：2026-10-08。五套原版与天境设计已写入源码，另有向日葵与狂瞳龙卷。此文档记录当前能力边界，结果见 [实施记录](../../OTHER_BOSS_IMPLEMENTATION.md)、[狂瞳龙卷](../../DEEP_AETHER_BOSS.md) 与 [验证记录](../../BOSS_VERIFICATION.md)。

## 一、群战人数：敌方总数最多六个

| 概念 | 当前含义 |
| --- | --- |
| 玩家队伍 | 最多六只，常规挑战每次派一只，换宠按原生流程 |
| 群战敌方 | 多个单位同时在场，包括 Boss，总数最多六个 |
| `minionCount` | 随从数 1–5；总人数 = 1 本体 + 此数 |
| 单 Boss | 不填 `bossBattle`，不是填 `minionCount=0` |
| 女仆协作 | 已有 TeamRocket 行动兼容；女仆增加己方在场单位，新组合仍需验证 |
| 原生六骑士 | 另一种已接入队伍：一个队伍入口 + 五个原有骑士，总数六个，不新生成另一套小队 |

上限可在 [EntityBattleProfile.BossBattle](../../src/main/java/dev/entitybattle/api/EntityBattleProfile.java) 看到：`minionCount` 校验 1–5。所读 Asymmetric Battles 的 `horde` 使用六个在场位置，非对称战将不同单位视为相邻；不按官方三打的左右距离推断第六个无法攻击。

[EntityBossHordes](../../src/main/java/dev/entitybattle/battle/EntityBossHordes.java) 显式构建名单，复用 Horde Encounters 入口与 Asymmetric Battles 规则。群攻减伤、死亡空槽、女仆协议、模型站位和动画需要一起验证；允许六个不等于每种 1 对 6 / 2 对 6 组合都已实测。

本批选择：魔石 1、女王 1、巨灵 6、凋灵 4、监守者 1。人数增加会带来更多总 HP、行动、持有物与回合时长，不能只把既有三人阵容复制翻倍。

当前不能只靠填字段实现：混合多种随从；逐成员分别设四招、六项或特性；中途召唤、复活、换波；七个以上同时在场或任意多玩家协作。已可统一覆盖本场随从装备与四招，逐成员数值与特性仍共享物种设定。

## 二、本批复用的原生功能

| 功能 | 应用 | 边界 |
| --- | --- | --- |
| 受击增防、以防御攻击 | 魔石持久力 + 扑击 | 多段、能力清除和道具组合待验证 |
| 敌方降能力时强化 | 女王不服输 | 原生选招，不规定触发后固定招序 |
| 自疗、临时属性变化 | 女王羽栖 | 原生 PP、当回合属性和顺序 |
| 范围防护 | 女王广域防守 | 不是所有单体攻击都能挡 |
| 忽略对手部分能力等级 | 监守者纯朴 | 不忽略所有数值和伤害修正 |
| 持有物限制变化招式 | 监守者突击背心 | 四招均为攻击，避免非法变化指令 |
| 声音、替身、隔音 | 爆音波、地狱突刺 | MC 音速伤害仅借视觉，不取消属性免疫 |
| 天气与属性修正 | 巨灵普通晴天 | 天气已有，新开晴 / 冷却条件需开发 |
| 体重威力、先制、群攻 | 重磅冲撞、电光一闪等 | 不重写伤害引擎；六位置组合需测试 |
| 恢复与输出道具 | 剩饭、树果、硬石头、眼镜等 | 每个 Boss 和每个随从均有道具 |

拟定 28 个四招槽位均采用当前引擎已有招式，中文核对 Cobblemon 1.8.1。自定义机制放在特性和来源生命周期，首版无需新专属伤害招式。

## 三、已写入源码的新功能

| 新功能 | 规则 | 实现职责 |
| --- | --- | --- |
| 亡骸甲胄 | 凋灵首次半血后一次防御 +1，之后有效特性阻挡原生球弹标签 | 正式特性，原生能力等级与防弹判断 |
| 熔核冷却 | 巨灵首次有效开场开普通晴；首次受到敌方冰招真实损伤后一次清普通晴并降特攻 / 速度 | 正式特性，原生天气与能力等级 |
| 统一转换资格 | 自动、道具、R 都检查同一规则 | 通用接口 + 天境剧情、凋灵蓄力、监守者特殊状态适配 |
| 来源生命周期结算 | 天境胜利执行地牢、进度和昼夜；自动转换中断保持宝可梦，临时转换中断恢复来源 | 通用持久恢复与天境来源适配 |
| 阶段与招式动作 | 凋灵护甲、巨灵冷却、各 Boss 攻击与声音 | 展示适配，不跑世界 AI 或额外伤害 |

新特性需正式脚本、中文名称 / 描述 / 消息和事件测试；不能只改名字。每场状态属于具体 Pokemon，不是物种全局变量，不带入 PC 或下一场；永久本场记录与普通能力等级分开。抑制、忽略、复制、换下、再获取均需遵循各文件规则，玩家奖励同样拥有该特性。

## 四、可以拓展但不纳入首版

| 设想 | 方向 | 当前边界 |
| --- | --- | --- |
| 魔石回合疲惫 | 累计有效行动后降防 / 降速 | 需定义失败、畏缩、睡眠和换下，首版先用持久力 |
| 监守者振动怒气 | 合法声音招式后有限强化 | 不等于世界监听 AI，首版先用纯朴 |

| Boss / 玩家强度分离 | 正式形态与奖励映射 | 当前同物种；需兼顾融合、玩偶、图鉴和存储 |
| 随从独立配置 | 通用战内数值 / 招式 / 特性覆盖 | 当前共享 species，不能说只改变临时小怪 |
| 更多多人协作 | 明确人数、等待、难度和奖励 | 女仆适配不等于通用多人 Raid |

来源死亡本来给钥匙、金剑、下界之星时保留；真实来源结算接管后，不再跑同次通用补发，避免两份物品 / XP。完整胜利的 1 级奖励是本项目功能，不附本场装备。

## 六、审阅后的实施顺序

1. **先补来源路径**：统一资格、持久快照、恢复保护和 Aether 原生结算；核对凋灵出生 / 死亡与监守者状态。剧情未适配前不部署新天境方案到正式地牢。
2. **写数据与特性**：五 Boss、两种随从，两个新特性配中文；已确认暮色尤其巫妖不改。
3. **验证真实组合**：单体及女仆 2 对 1，凋灵 1 / 2 对 4，巨灵 1 / 2 对 6，重点第六目标、范围、死亡空槽、换宠和道具。
4. **接动作与展示**：沿用官方模型仓库通路和来源 renderer，检查阶段、资料 / 头像 / 玩偶；不改世界尺寸来修一个 GUI。
5. **验原作流程**：真实三类地牢、原版出生 / 死亡、进度、结算及中断重启。隔离测试检查协议事件，结构和视觉仍需实机。
6. **构建部署 JAR**：所有配置与代码进入源码；整合包只接收 JAR。审阅文件不会自动改变游戏，部署时报告真正完成和待验收项。

修改位置：原版 [vanilla_mobs.json](../../src/main/resources/data/entitybattle/battle_profiles/vanilla_mobs.json)，天境 [pack_mobs.json](../../src/main/resources/data/entitybattle/battle_profiles/pack_mobs.json)，species 与能力在 `src/main/resources/data/entitybattle/`。外部作者可复用数据；来源剧情仍需生命周期适配，复制 Boss 名称不自动获得所有行为。

现有能力总表见 [功能预设表.md](功能预设表.md)，天境证据、门槛和失败规则见 [天境剧情与结算.md](天境剧情与结算.md)。
